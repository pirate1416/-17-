# 스팀 리뷰 측면별 감정 분석 (Aspect-Based Sentiment Analysis)

> 자연어처리 미니프로젝트 · 17조 (김주왕) · 2026.10.13 발표
> 주제: "내부를 이해하고 하나를 바꾸어 보자"

## 1. 문제 정의

기존 게임 리뷰 감성 분석은 리뷰 전체를 **긍정 / 부정 하나**로만 판정한다.
하지만 실제 리뷰에는 칭찬과 불만이 섞여 있다.

> "그래픽은 진짜 예쁜데 최적화가 최악이라 환불했습니다" → 기존 판정: 부정 (1개)

개발사·마케터가 시장 분석에서 알고 싶은 것은 **무엇이 좋고 무엇이 문제인지**다.
이번 프로젝트는 리뷰를 측면(그래픽 · 스토리 · 가격 · 최적화 · 번역/현지화)별로 나누어
측면마다 긍정/부정을 판정하는 것을 목표로 한다.

## 2. 데이터셋

| 항목 | 내용 |
|---|---|
| 이름 | 스팀 한국어 리뷰 감성 코퍼스 |
| 출처 | [bab2min/corpus](https://github.com/bab2min/corpus/tree/master/sentiment) (`sentiment/steam.txt`) |
| 규모 | 100,000건 (중복 제거 후 99,892건) |
| 형식 | `라벨 \t 리뷰` (헤더 없음) |
| 라벨 | 1 = 긍정, 0 = 부정, 약 50:50 균형 |
| 길이 | 형태소 기준 평균 약 15, 최대 64 |
| 한계 | 리뷰 전체 단위 라벨만 존재, **측면 라벨 없음** |

## 3. 참조 코드 분석

- 원본: 위키독스 「딥 러닝을 이용한 자연어 처리 입문」 [10-08 BiLSTM으로 한국어 스팀 리뷰 감성 분류하기](https://wikidocs.net/94748)

처리 흐름:

1. **정제**: 정규식으로 한글과 공백만 남김
2. **형태소 분석**: Mecab으로 토큰화 후 불용어 제거
3. **정수 인코딩**: 1회만 등장한 단어 제외 (원본 기준 단어 집합 18,941개)
4. **패딩**: 길이 60으로 통일 (학습 리뷰의 99.99% 보존)
5. **모델**: Embedding(100) → Bidirectional LSTM(128) → Dense(1, sigmoid)
6. **결과**: 원본 기준 테스트 정확도 **78.93%**

핵심 한계: 출력이 리뷰당 **긍정 확률 하나**뿐이라, 리뷰 안의 여러 측면을 구분할 수 없다.

## 4. 사용할 NLP 모델의 원리

자세한 내용은 [`docs/model_principles.md`](docs/model_principles.md) 참고.

- **BiLSTM (참조 코드)**: LSTM 두 개를 반대 방향으로 돌려 앞뒤 문맥을 모두 반영. 분류 시 순방향 마지막 은닉 상태와 역방향 첫 은닉 상태를 결합.
- **KcELECTRA (구현에 사용할 모델)**: 생성기가 일부 토큰을 바꿔치기하면 판별기가 각 토큰의 원본/교체 여부를 맞히는 방식(Replaced Token Detection)으로 사전학습. 뉴스 댓글 약 17GB로 학습되어 구어체·신조어에 강함. NSMC 정확도 91.97% (v2022).

## 5. 기존 구현 vs 추가할 내용

| 구분 | 기존 (참조 코드) | 추가 (이번 프로젝트) |
|---|---|---|
| 분석 단위 | 리뷰 전체 1개 | 리뷰 속 문장·측면별 |
| 출력 | 긍정 / 부정 | 측면 × 긍정 / 부정 |
| 모델 | BiLSTM | KcELECTRA 파인튜닝 |
| 답하는 질문 | 평가가 좋은가? | 무엇이 좋고 무엇이 문제인가? |

## 6. 구현 계획

1. **문장 분리**: 리뷰를 문장·절 단위로 분리 ("~는데", "~지만" 등 연결 어미 기준 포함)
2. **측면 태깅**: 측면별 키워드 사전으로 각 절에 측면 부여 (예: 프레임·렉 → 최적화)
3. **감정 분류**: 스팀 리뷰로 파인튜닝한 KcELECTRA로 절마다 긍정/부정 판정
4. **측면별 집계**: 게임 단위로 측면마다 긍정 비율 산출

### 예상 한계와 대응

- 측면 정답 라벨 없음 → 키워드 기반 태깅 + 일부 수작업 검수
- 한 문장에 측면 여러 개 → 연결 어미 기준 절 단위 분리
- 반어·비꼼 ("최적화 참 잘했네요") → 오류 사례로 따로 분석
